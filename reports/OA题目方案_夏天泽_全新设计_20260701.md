## 一、业务场景：多源科研情报聚合与证据链审计 Agent

**场景名称**：科研文献证据链审计 Agent（Research Evidence Chain Auditor）

**场景描述**：候选人需要构建一个 Agent Pipeline，输入是围绕某个前沿 AI 课题（"多模态大模型幻觉缓解方法"）的 5-7 种异构源材料，Agent 自动完成采集→解析→对齐→矛盾检测→验证→报告生成的完整链路。

**与候选人背景的呼应**：
- 候选人研究多模态大模型幻觉缓解（EMNLP 2025）→ 输入材料围绕幻觉课题
- 候选人研究幻觉检测（共同一作）→ 矛盾检测环节直接对应
- 候选人研究表征工程 → 知识对齐环节可发挥
- 候选人数理基础极好 → 置信度建模、统计冲突检测

**与合同审查场景完全不同** ✅

## 二、三段式递进题目设计

### 第一段：基础闭环（~2小时，40分）

| 维度 | 内容 |
|------|------|
| **输入** | 3种异构源：论文PDF（含表格）、技术博客HTML、实验Benchmark CSV |
| **任务** | 提取声明→跨源对齐→输出结构化JSON报告 |
| **植入噪声** | 数值矛盾（正文vs表格）、术语不一致、夸张表述、格式漂移 |
| **考察重点** | Pipeline完整性(12分)、格式鲁棒性(10分)、基础幻觉控制(8分)、结构化输出(6分)、代码质量(4分) |

### 第二段：动态泛化（~1.5小时，35分）

| 维度 | 内容 |
|------|------|
| **输入** | 新增2种源：会议演讲转录文本、Reddit讨论帖 |
| **任务** | 扩展Pipeline支持新源、检测3+处信息冲突、调用验证工具、更新报告 |
| **植入冲突** | 数值冲突（口误导致）、主张冲突（博客夸张vs论文数据）、排名冲突（Benchmark vs 社交媒体） |
| **考察重点** | 可扩展性设计(12分)、冲突检测与消解(10分)、可信度评分(8分)、证据链追踪(5分) |

### 第三段：极限压测（~1小时，25分）

| 维度 | 内容 |
|------|------|
| **输入** | 损坏PDF、恶意噪声CSV（NaN/SQL注入）、LLM伪造文本、实时状态查询 |
| **任务** | 优雅降级、检测伪造信息、输出中间状态快照 |
| **考察重点** | 错误恢复(8分)、降级策略(7分)、恶意输入防护(5分)、增量输出(5分) |

## 三、7种噪声类型（三层递进）

| # | 噪声类型 | 层次 | 覆盖缺陷 | 植入位置 |
|---|---------|------|---------|---------|
| 1 | 数值矛盾 | 显性 | 信息冲突 | S1论文正文vs表格、S4 CSV vs S1 |
| 2 | 引用幻觉 | 显性 | 幻觉 | S1参考文献（DOI无效）、S2 README |
| 3 | 格式漂移 | 显性 | 格式漂移 | S4 CSV（% vs 小数混用、日期格式不一致） |
| 4 | 时序矛盾 | 隐性 | 信息冲突 | S3转录 vs S1（作者说放弃了方法A但论文仍推荐） |
| 5 | 权威冲突 | 隐性 | 信息冲突+幻觉 | S6 Wikipedia vs S1（过时结论） |
| 6 | 语义歧义 | 隐性 | 幻觉 | S3转录模糊表述、S2 README夸大声明 |
| 7 | 对抗性噪声 | 对抗性 | 三大缺陷全部 | NaN注入、SQL注入、LLM生成"看起来合理但错误"文本 |

## 六、针对候选人特点的出题策略

### 放大优势
1. **幻觉检测研究 → 解题钥匙**：植入引用幻觉陷阱，让他的研究直觉直接发挥作用
2. **表征工程 → 知识对齐**：脚手架用字符串匹配，他应改用embedding-based对齐
3. **数理基础 → 置信度建模**：设计统计陷阱（方差大样本小），考察统计显著性意识
4. **多模态理解 → 图文一致性**：论文图表与文本的微妙不一致
5. **LLM过度自信认知 → 模糊声明处理**：未量化的声明应标记为低置信度

### 暴露短板
1. **可扩展性设计**：第一段硬编码源类型 → 第二段被迫重构
2. **错误处理**：脚手架无try-catch → 第三段异常同时施加
3. **设计文档**：第二段要求写架构说明
4. **增量输出**：第三段要求中间状态快照

### 侧面验证简历真实性
- 候选人自己EMNLP论文结论篡改（降低篡改幅度，加安全阀提示）
- 统计陷阱验证数理基础
- 伪造数据验证实验能力

## 七、技术方案

### 技术栈
- Python 3.11+，不限定Agent框架
- PyMuPDF (fitz) 用于PDF解析
- pandas 用于CSV处理
- Mock LLM Server（Flask/FastAPI）模拟LLM调用
- jsonschema 用于输出校验

### Mock LLM 设计
- 语义匹配响应（基于关键词匹配请求内容）
- 10%随机幻觉率（逼候选人设计规则兜底）
- 第三段模拟超时（35秒延迟）和伪造数据

## 九、会议结论

本次会议完成了为候选人夏天泽全新设计 OA 题包方案的全部讨论，达成以下共识：

1. **业务场景**：科研文献证据链审计 Agent — 全新设计，与合同审查完全不同，天然包含5+异构源和多种噪声类型
2. **三段式设计**：基础闭环(2h) → 动态泛化(1.5h) → 极限压测(1h)，总计4.5小时
3. **噪声设计**：7种噪声类型，三层递进（显性→隐性→对抗性）
4. **评分体系**：100分制，39%分值压在Pipeline设计直觉上
5. **脚手架缺陷**：6个可控缺陷，覆盖架构/性能/安全/可靠性维度
6. **针对性策略**：放大LLM底层理解优势，暴露Agent经验短板，侧面验证简历真实性
7. **技术方案**：Python + Mock LLM + Docker，预估准备工时3.5个工作日
