## 议题 2：弱点打击精准度

### 结论：95% 精准（陈总监）/ 83% 精准（李华）

| 前次 OA 弱点 | OA_v2 打击方式 | 精准度 |
|-------------|---------------|--------|
| 无 try/except | 15% ConnectionError 强制触发异常 | ✅ 精准 |
| 无重试 | 指数退避重试要求 + 15% 确保触发 | ✅ 精准 |
| 无 JSON 解析容错 | 5% 非 JSON + fallback 要求 | ✅ 精准 |
| 无日志/监控 | processing_log 要求 | ✅ 精准 |
| Prompt Engineering 薄弱 | evidence state 迫使 prompt 精细化 | ✅ 间接打击 |
| **无超时控制** | ❌ 未覆盖 | ⚠️ 遗漏 |

**李华建议**：在 call_llm 中增加 5% 概率的"慢响应"（30 秒后返回），并在题目中明确要求"设置合理的超时时间"。同时增加优雅降级要求。

## 议题 3：OA 合规性（四不准与三必须）

### 结论：完全合规 ✅

| 要求 | 检查结果 |
|------|---------|
| ❌ 不准变成纯算法题 | ✅ 合规 — 核心是 Pipeline 设计 |
| ❌ 不准变成纯 Prompt 语法调优题 | ✅ 合规 — Prompt 只是工具 |
| ❌ 不准考察特定框架熟练度 | ✅ 合规 — 不要求 LangChain/LlamaIndex |
| ❌ 不准限定死唯一的解题路线 | ✅ 合规 — 多条可行方案 |
| ❌ 不准提供暗示 Workflow 结构的脚手架 | ✅ 合规 — main_init.py 只提供空壳 |
| 🔗 必须有复杂业务目标和噪声输入 | ✅ 合规 — 15 个来源含冲突/过时/缺失 |
| 🔗 必须有可量化输出质量目标 | ✅ 合规 — "连续运行 5 次至少 4 次成功" |
| 🔗 必须有极大容错空间 | ✅ 合规 — "代码可以粗糙，边界可以有 Bug" |

## 议题 4：输入材料复杂度

### 结论：足够复杂，无法 One-Shot 解决 ✅

| 复杂性维度 | 示例 | 评价 |
|-----------|------|------|
| 冲突信息 | 退款策略 v2（当前）vs v3（计划中）vs v1（已废弃） | ✅ 三层冲突 |
| 过时信息 | v1 策略（2025-06-01）、v1 质量标准（2025-12-01） | ✅ 明确标注时间 |
| 缺失信息 | CUST-3381 历史退款次数、各策略版本使用频率 | ✅ 多处信息缺口 |
| 关联线索 | CUST-3381 3 天 3 次工单（#4521、#4542、#4548） | ✅ 跨工单关联 |
| 内部主观意见 | Slack 讨论中的个人观点 | ✅ 需区分事实和观点 |
| 版本管理 | 策略版本 + 评估标准版本 + 产品路线图版本 | ✅ 多版本共存 |

**李华评价**：策略版本冲突和跨工单关联是两个关键设计亮点，直接对应候选人简历中声称的能力。

**赵雷评价**：15 个来源的复杂度足够防止 One-Shot。一个 One-Shot 的候选人可能会把路线图初稿当作确定计划、把旧策略当作当前策略。

## 议题 7：夸大暴露

### 结论：GRPO/RL/vLLM/DeepSpeed 在本题无自然落脚点，需面试追问补充

**设计思路**：题目完全不涉及这些技术，观察候选人是否在不需要时仍然提及它们。

**王工建议**：
1. 在 README 中增加追问："如果要将此 Pipeline 部署到生产环境每天处理 10 万次请求，你会如何优化？"
2. 在面试中重点追问 GRPO/RL/vLLM/DeepSpeed 的具体使用场景
3. 接受现实：没有任何一道 OA 能覆盖所有声称。OA_v2 验证了核心声称（Agent 系统设计），如果核心声称被证伪，边缘声称的真假已不重要。
