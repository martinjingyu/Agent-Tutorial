## 最终推荐方案

### 题目名称
**「智能合同审查与条款对齐系统」**

### 业务场景
某跨国法务外包公司每天收到大量非结构化合同文档（PDF/扫描件/邮件正文），需要自动提取关键条款，与内部合规知识库进行对齐审查，输出结构化的审查报告。合同来源多样、格式混乱、语言混杂（中英混合）、存在OCR错误、手写批注、扫描倾斜等真实文档缺陷。

**核心痛点**：LLM幻觉导致条款误判、上下文窗口限制导致长合同截断、噪声输入导致提取漂移。

## 一、输入材料设计（约20-30份合同片段）

### 噪声类型

| 噪声类别 | 具体表现 |
|---------|---------|
| **OCR识别错误** | "赔偿"→"赔尝"、"违约金"→"违金约"、"confidential"→"confldentlal" |
| **扫描倾斜** | 部分文字缺失或扭曲 |
| **水印覆盖** | 水印遮挡关键条款文字 |
| **手写批注** | 批注遮挡正文，LLM可能误将批注当作条款 |
| **LLM特有噪声①** | 长上下文注意力漂移：合同前段定义"交货期=30天"，后段LLM错误解读为"交货期=45天" |
| **LLM特有噪声②** | 指代消解错误：LLM将"该条款"错误关联到前文的不同实体 |
| **LLM特有噪声③** | 格式漂移：LLM在长合同处理中输出格式逐渐偏离初始格式 |

### 材料包构成

| 类型 | 内容 | 噪声特征 |
|------|------|----------|
| **合同A** | 10页NDA，中英混合，含扫描件 | OCR错字、手写批注遮挡条款 |
| **合同B** | 8页SaaS服务协议，纯英文 | 表格格式混乱、页眉页脚干扰、条款编号跳跃 |
| **合同C** | 5页采购合同，中文为主 | 扫描倾斜、水印覆盖部分文字、段落间无空行 |
| **合规知识库** | 20条合规规则（JSON格式） | 规则间存在2条隐含冲突（需优先级消解） |
| **参考模板** | 1份标准审查报告样例 | — |

### 量化目标（满分基准线）

| 指标 | 目标值 |
|------|:-----:|
| 条款提取召回率 | ≥ 85% |
| 对齐判断准确率 | ≥ 80% |
| 幻觉条款数 | ≤ 2（共约25个真实条款） |
| 自纠正次数 | ≥ 3 |
| 平均回译相似度 | ≥ 0.85 |

## 三、评分维度（总分100分）

| 维度 | 权重 | 考察点 |
|------|:----:|--------|
| **A. 动态拆解与状态传递** | **30分** | 长合同分块策略、跨块条款编号追踪、块间一致性维护、指代消解 |
| **B. 输入建模与边界控制** | **25分** | OCR噪声建模、格式无关提取、LLM特有噪声（注意力漂移/指代错误）建模、低置信度片段标记与拒绝强行提取 |
| **C. 质量闭环与定向修复** | **30分** | 回译验证机制、幻觉检测与定向修复、修复后验证、置信度校准、quality_metrics自评 |
| **D. Pipeline设计直觉** | **15分** | Pipeline编排合理性（10分）、可观测性设计/日志/追踪/质量指标上报（10分）→ 总分15分（合并后） |

### 评分细则

#### A. 动态拆解与状态传递（30分）
- **分块策略（10分）**：是否根据token数/条款边界自适应切分？是否考虑语义完整性？
- **跨块状态传递（10分）**：条款编号跨块是否追踪？指代消解是否正确？
- **块间一致性维护（10分）**：同一术语在不同分块中的解读是否一致？

#### B. 输入建模与边界控制（25分）
- **噪声建模（10分）**：是否对OCR错误/注意力漂移/指代错误做了显式建模？
- **格式无关提取（8分）**：是否支持表格/段落/列表等多种格式？
- **边界检测（7分）**：是否有明确的边界控制（置信度<0.6→转人工）？

#### C. 质量闭环与定向修复（30分）
- **回译验证机制（12分）**：是否设计了条款回译验证？回译相似度计算是否合理？
- **幻觉检测与定向修复（10分）**：是否能检测幻觉？是否只重新处理有问题的条款？
- **修复验证（8分）**：修复后是否再次验证？是否有修复次数上限防止无限循环？

#### D. Pipeline设计直觉（15分）
- **Pipeline编排（8分）**：模块划分是否合理？阶段间契约是否明确？
- **可观测性（7分）**：是否有日志/追踪？是否能定位Pipeline中的瓶颈和失败点？

## 四、三段式递进设计

### 🟢 Level 1：基础闭环（40分）

**任务**：处理1份噪声最低的合同（合同C），输出审查报告。

**考察点**：
- 基本的LLM调用编排（提取→对齐→输出）
- 简单的输入清洗（去水印/去页眉页脚）
- 单次LLM调用完成条款提取

**容错空间**：允许人工指定分块策略，不要求自纠正。

**评分上限**：40分（即使满分也只到及格线，逼迫考生思考进阶设计）

---

### 🟡 Level 2：动态泛化（35分）

**任务**：处理全部3份合同，其中合同A含严重OCR噪声，合同B含表格混乱，所有合同含LLM特有噪声（注意力漂移、指代消解错误、格式漂移）。

**新增考察点**：
- 动态分块策略（根据token数/条款边界自适应切分）
- 跨块状态传递（条款编号跨块追踪、指代消解）
- 输入边界控制（检测并标记低置信度片段，不强行提取）
- **回译验证**：对提取的条款做回译验证，检测LLM幻觉
- **定向修复**：发现幻觉后只重新提取有问题的条款

**容错空间**：允许部分条款提取失败，但必须标记confidence<0.5并说明原因。

---

### 🔴 Level 3：极限压测（25分）

**任务**：合规知识库中存在2条隐含冲突的规则（如R-07要求赔偿上限100%，R-12要求特殊品类上限50%），需设计优先级消解逻辑。同时要求Pipeline具备可观测性设计。

**新增考察点**：
- 规则冲突检测与优先级推理
- 定向修复：对特定条款类型（如赔偿条款）做二次深度审查
- 质量闭环：输出中的`quality_metrics`必须由LLM自评生成，而非硬编码
- Pipeline可观测性：输出中间步骤的日志/置信度轨迹

**容错空间**：规则冲突消解允许多种合理策略（规则优先级/上下文优先/用户确认），只要推理过程合理即可得分。

## 五、方案与约束对照

| 约束 | 满足方式 |
|------|---------|
| **测LLM缺陷控制力** | 三个维度全覆盖：动态拆解（分块+状态传递）、输入建模（OCR+LLM特有噪声）、质量闭环（回译验证+定向修复） |
| **不准变算法题/Prompt调优题** | 核心是Pipeline架构设计，不是写prompt技巧或算法实现 |
| **复杂业务+噪声输入** | 跨国法务场景+OCR错误+扫描倾斜+水印+手写批注+LLM特有噪声（注意力漂移/指代错误/格式漂移） |
| **可量化输出质量** | 召回率/准确率/幻觉数/自纠次数/回译相似度，全部可自动评分 |
| **极大容错空间** | L1允许人工指定策略，L2允许标记失败，L3允许多种合理消解 |

## 七、会议结论

三位专家（Alice、Bob、Carol）经过充分讨论，一致推荐 **「智能合同审查与条款对齐系统」** 作为候选人夏天泽的OA题目方案。

**核心推荐理由**：
1. 对候选人最友好 — LLM底层理解成为最大武器
2. 三段式递进最清晰 — L1→L2→L3增量明确
3. 容错空间最大 — 对无Agent经验者最公平
4. 短板最容易修补 — 增强质量闭环维度后成为最均衡方案

**三个关键增强**（由Bob和Carol提出，Alice接受）：
1. 加入"条款回译验证"机制（质量闭环权重提升至30%）
2. 加入LLM特有噪声类型（注意力漂移、指代消解错误、格式漂移）
3. 架构分拆为Pipeline编排(10分)+可观测性设计(10分)，合并后总分15分
