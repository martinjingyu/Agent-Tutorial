# 会议结论：AI 算法实习生筛选流程评估与改进建议

> 会议时间：2026-06-29
> 参与者：张三（资深算法工程师）、李四（HR 招聘负责人）、王五（团队负责人）
> 讨论形式：两轮结构化讨论（先开放分享，后聚焦优先级）

---

## 当前流程评估

**现有流程环节：** 简历收集 → 简历初筛 → 笔试/编程测试 → 技术一面（基础面）→ 技术二面（综合面）→ HR面 → Offer发放

**做得好的方面：**
1. ✅ 项目深挖环节能有效区分"真做过"和"挂名"的候选人
2. ✅ 多轮交叉面试减少单个人主观偏见
3. ✅ 笔试标准化程度高，减少了人为偏见

## 四大核心问题（按严重程度排序）

| 问题 | 严重程度 | 影响 |
|------|---------|------|
| ① 简历初筛过度依赖硬标签 | 🔴 高 | 潜力型候选人被误筛，同质化简历区分度下降 |
| ② 面试标准不统一，缺乏量化评分 | 🔴 高 | 同一候选人面不同面试官结果不同，决策噪声大 |
| ③ 手撕代码权重过高，与实际能力脱节 | 🟡 中高 | "高分低能"现象，误杀有科研/工程潜力但刷题少的候选人 |
| ④ 流程周期太长（3-4周） | 🟡 中高 | 优秀候选人被竞争对手截胡 |

## 优先改进建议（Top 3，按实施顺序）

### 🥇 第一优先：建立标准化面试评估体系
- **具体措施**：
  - 设计 4-5 维度 × 5 分制评分 Rubric（算法基础、ML理论、工程能力、系统设计、沟通表达）
  - 每个维度附具体行为锚定（behavioral anchors）
  - 面试官认证机制：培训 + 旁听 + 试面
  - 每月一次面试官校准会，对齐评分标准
- **投入产出**：低投入（模板+培训），高收益（面试质量提升+数据驱动决策）
- **见效时间**：2-4 周

### 🥈 第二优先：重构技术评估内容，降低手撕代码权重
- **具体措施**：
  - 引入轻量级 Home Assignment（4-6小时端到端ML任务）或 Mini Project（48小时）
  - 增加业务场景开放题（推荐/搜索、NLP/LLM、通用ML三个方向）
  - 笔试改为"3+2+1"模式（3道算法+2道ML+1道业务场景）
  - 提交后安排 15 分钟 code review 面防作弊
- **投入产出**：中投入（题目设计），高收益（更准确的能力评估）
- **见效时间**：4-8 周

### 🥉 第三优先：建立快速通道机制，缩短优秀候选人流程
- **具体措施**：
  - 触发条件：顶会一作 / 大厂实习优秀 / 笔试前5% / 高质量开源项目（满足2条）
  - 流程：简历通过 → 1轮综合技术面 → HR面 → 5个工作日内发Offer
  - 特别优秀者可跳过笔试
- **投入产出**：中投入（流程调整），高收益（减少候选人流失）
- **见效时间**：1-2 周

## 实施路线图

| 时间 | 动作 | 负责人 |
|------|------|--------|
| 第 1-2 周 | 设计评分 Rubric 初版 + 面试官培训材料 | 王五（牵头）+ 李四（协调） |
| 第 3-4 周 | 组织第一次面试官校准会 + 启动面试官认证 | 王五 + 张三 |
| 第 5-6 周 | 设计 Home Assignment 模板 + 业务场景题库 | 张三（牵头） |
| 第 7-8 周 | 小范围试点 Home Assignment + 快速通道 | 李四（协调排期） |
| 第 9-12 周 | 全量推广 + 建立月度校准机制 | 全体 |

## 关键原则

1. **评分 Rubric 先行**：没有统一的度量衡，其他改进效果无法衡量
2. **贴近实际工作**：评估内容应反映日常工作中的核心能力（代码质量、实验设计、业务理解），而非刷题能力
3. **效率与质量并重**：快速通道解决效率问题，Home Assignment 解决深度问题，两者互补
4. **持续迭代**：每月复盘评分数据，持续优化流程
