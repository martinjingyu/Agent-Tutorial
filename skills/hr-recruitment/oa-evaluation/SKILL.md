# OA Evaluation (在线编程测试评估)

## 何时使用

当需要对候选人的 OA（Online Assessment）编程题提交进行评估时使用。本 skill 指导 agent 如何：
1. 收集 OA 题目描述和评价标准
2. 读取候选人提交的代码
3. 基于多维评价标准进行结构化评估
4. 输出评估报告

## 前置条件

- 候选人已完成 Stage 1 筛选（profile.json 存在）
- OA 题目描述和评价标准已提供或可从内部文档获取
- 候选人提交的代码文件已存在

## 目录结构约定

所有 OA 评估相关文件保存在 `candidates/{候选人姓名}/OA/` 下：

```
candidates/{候选人姓名}/
├── profile.json                    # Stage 1 简历数据
├── OA/
│   ├── README.md                   # OA 任务概述（题目、要求、截止时间等）
│   ├── source_material.md          # 题目详细描述（如有）
│   ├── INTERNAL_EVALUATION.md      # 内部评价标准（评分维度、权重、扣分规则）
│   ├── schema.json                 # 结构化评估 schema（定义评估维度）
│   ├── evaluate.py                 # 评估执行脚本（按 schema 逐项评估）
│   ├── {提交文件1}.py              # 候选人提交的代码文件
│   └── evaluation-report.md        # 最终评估报告（输出）
```

## 评估流程

### Step 1: 收集 OA 信息

读取或收集以下材料：
- **OA 题目描述** — 问题陈述、输入输出规范、示例
- **内部评价标准** — 评分维度、权重、扣分规则、通过/不通过阈值
- **候选人提交代码** — 候选人提交的源文件

### Step 2: 定义评估 Schema

创建 `schema.json`，定义结构化评估维度。典型维度包括：

```json
{
  "dimensions": [
    {
      "name": "correctness",
      "label": "正确性",
      "weight": 0.35,
      "max_score": 100,
      "criteria": ["通过所有测试用例", "边界条件处理", "异常输入处理"]
    },
    {
      "name": "code_quality",
      "label": "代码质量",
      "weight": 0.20,
      "max_score": 100,
      "criteria": ["代码可读性", "命名规范", "模块化设计", "注释质量"]
    },
    {
      "name": "algorithm",
      "label": "算法与数据结构",
      "weight": 0.25,
      "max_score": 100,
      "criteria": ["算法正确性", "时间复杂度", "空间复杂度", "数据结构选择"]
    },
    {
      "name": "robustness",
      "label": "鲁棒性",
      "weight": 0.10,
      "max_score": 100,
      "criteria": ["错误处理", "输入验证", "边界检查"]
    },
    {
      "name": "innovation",
      "label": "创新与扩展",
      "weight": 0.10,
      "max_score": 100,
      "criteria": ["解题思路创新性", "扩展性考虑", "优化建议"]
    }
  ],
  "pass_threshold": 70,
  "fail_threshold": 50
}
```

### Step 3: 编写评估脚本

创建 `evaluate.py`，包含：
- 读取 `schema.json` 加载评估维度
- 读取候选人提交代码
- 逐维度评估并打分
- 计算加权总分
- 输出结构化评估结果

### Step 4: 执行评估

运行评估脚本，对候选人提交进行逐维度评估。

### Step 5: 生成评估报告

输出 `evaluation-report.md`，包含：
- 候选人基本信息
- OA 题目概述
- 各维度评分及理由
- 加权总分
- 结论（通过/待定/不通过）
- 改进建议

## 评估维度详解

### 1. 正确性 (Correctness) — 权重 35%
- 代码是否通过所有测试用例
- 是否处理了边界条件（空输入、极值、特殊值）
- 是否处理了异常输入

### 2. 代码质量 (Code Quality) — 权重 20%
- 代码可读性：变量命名、函数划分、缩进风格
- 是否遵循 PEP8 或项目规范
- 注释是否充分且有意义
- 是否有重复代码或过度复杂的设计

### 3. 算法与数据结构 (Algorithm) — 权重 25%
- 算法选择是否最优
- 时间/空间复杂度分析
- 数据结构选择是否合理
- 是否有优化空间

### 4. 鲁棒性 (Robustness) — 权重 10%
- 是否有输入验证
- 是否有错误处理机制
- 边界检查是否完善

### 5. 创新与扩展 (Innovation) — 权重 10%
- 解题思路是否有创新点
- 代码是否易于扩展
- 是否考虑了实际应用场景

## 评分标准

| 分数区间 | 等级 | 说明 |
|---------|------|------|
| 90-100 | 优秀 | 代码完美，思路清晰，有创新 |
| 75-89 | 良好 | 代码正确，质量较高，有小瑕疵 |
| 60-74 | 合格 | 基本正确，但存在明显不足 |
| 40-59 | 待改进 | 部分正确，有较大改进空间 |
| 0-39 | 不合格 | 严重错误或未完成 |

## 结论判定

| 加权总分 | 结论 |
|---------|------|
| ≥ pass_threshold (默认70) | ✅ 通过 |
| ≥ fail_threshold (默认50) | 🔶 待定（需人工复核） |
| < fail_threshold (默认50) | ❌ 不通过 |

## 注意事项

1. **评估应基于代码本身**，不要因候选人背景（学校、学历）影响评分
2. **扣分需给出具体理由**，引用代码中的具体行号或片段
3. **如代码无法运行**，在正确性维度扣分，但算法维度仍可评估
4. **如候选人提交多个文件**，逐一评估后给出综合评分
5. **评估报告应包含改进建议**，对候选人后续面试有参考价值
6. **OA 评估是 Stage 2 流程**，应在 Stage 1 筛选通过后进行
