# OA 出题内部标准

## 四不准与三必须

### ❌ 四不准
1. **不准变成纯算法题** — 不是 LeetCode 风格的数据结构/算法题，而是考察 Agent/Pipeline 设计能力
2. **不准变成 Prompt 语法调优题** — 不是考察候选人会不会写 Prompt 模板语法，而是考察对 LLM 缺陷（幻觉、失控、格式漂移）的控制力
3. **不准依赖特定框架** — 不考察 LangChain/LlamaIndex 等框架的 API 熟练度，候选人可以用任何方式实现
4. **不准限定唯一解题路线** — 题目应允许多种实现方案，考察候选人的设计直觉而非标准答案

### 🔗 三必须
1. **必须有复杂业务目标与噪声输入** — 模拟真实业务场景，输入材料包含冲突/冗余/缺失信息
2. **必须有可量化输出目标** — 输出质量可以客观比对（如结构化 JSON、事实准确率、格式合规率）
3. **必须有极大容错空间** — 2小时笔试允许代码粗糙，分值全压在 Pipeline 设计直觉上

## 三段式题目演进模板

### 第一段：基础闭环（已知维度抽取与生成）
- 给候选人明确的维度/字段列表
- 要求从原始材料中提取信息，按给定结构输出
- 考察点：信息抽取能力、结构化输出能力、对 LLM 格式漂移的控制

### 第二段：动态泛化（未知维度自适应）
- 不给固定维度，让候选人自主分析材料结构
- 要求候选人设计输出大纲/Schema
- 考察点：分析能力、设计能力、对材料结构的理解

### 第三段：极限压测（海量异构数据流架构设计）
- 面试讨论环节，非笔试
- 给出海量/异构/实时数据流场景
- 考察点：架构设计能力、系统思维、对 Agent Pipeline 的理解

## 评分维度与权重建议

| 维度 | 权重 | 说明 |
|------|:----:|------|
| Pipeline 设计直觉 | 40% | 整体架构设计、模块划分、数据流设计 |
| LLM 缺陷控制 | 25% | 对幻觉/格式漂移/失控的处理策略 |
| 代码质量 | 15% | 可读性、错误处理、模块化（允许粗糙） |
| 输出质量 | 20% | 输出结果的准确性、完整性、结构化程度 |

## 降档与 FAIL 机制

- **直接 FAIL**：代码无法运行、核心功能缺失、抄袭/作弊
- **降一档**：Pipeline 设计有明显缺陷、LLM 缺陷完全未处理
- **加分项**：设计了优雅的容错机制、输出质量超出预期、有创新性设计
